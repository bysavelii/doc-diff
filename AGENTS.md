# doc-diff

Правила этого проекта для агентов и людей. Процесс разработки задаёт Cyberzavod: этапы, роли и общие принципы приходят из его harness, здесь — только то, что относится к проекту. Файлы конкретного агента (например, `CLAUDE.md`) создаёт `cyberzavod sync` поверх этого файла.

## О проекте

- Продукт: doc-diff показывает, что изменилось между двумя версиями договора в PDF или DOCX: добавленные, удалённые, изменённые и перенесённые пункты. Результат — отчёт в HTML.
- Для кого: юристы, фрилансеры, арендаторы — все, кому присылают «исправленную версию» договора и нужно быстро понять, что в ней поменяли.
- Язык и инструменты: Python 3.12+; зависимости и окружение — uv, линтер и форматтер — ruff, типы — mypy, тесты — pytest.
- Язык текстов: сообщения пользователю (интерфейс, ошибки, отчёт) и комментарии в коде — по-русски; идентификаторы (имена модулей, классов, функций, переменных) — по-английски.
- Коммиты: [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/); тип и область — по-английски, описание — по-русски. Пример: `feat(parser): извлекать пункты из DOCX`.

## Команды

- Форматирование: `uv run ruff format`.
- Проверки (`verification.commands` в `.cyberzavod/project.json`):
  - `make check` — по очереди `ruff check`, `ruff format --check`, `mypy` (strict, `src` и `tests`) и `pytest`.

## Код и тесты

Правила кода и тестов проекта: по ним пишет исполнитель, проверяют тестировщик и ревьюер.

- Раскладка: код — в `src/doc_diff/`, тесты — в `tests/`; сгенерированные документы и шрифт для них — в `tests/builders.py` и `tests/fixtures/`.
- Чистые модули (`alignment`, `clauses`, `formatting`, `page_margins`, `paragraphs`, `spacing`, `text_report`, `word_diff`) не импортируют pypdf, python-docx и argparse. Библиотеки для чтения файлов подключаются только в адаптерах `*_reader.py`, разбор командной строки — только в `cli.py`.
- Пробельные символы в тексте абзацев и ячеек таблиц схлопывает одна функция `collapse_whitespace` (`spacing.py`): PDF- и DOCX-адаптер используют её обе, чтобы один договор в двух форматах не расходился на пустом месте.
- Ошибки, которые видит пользователь, — `DocumentReadError` с готовым русским сообщением. Библиотечные исключения перехватываются только в адаптерах и только перечисленные, и только вокруг вызовов самой библиотеки (собственная логика в `try` не попадает); неожиданное исключение — дефект, его не глотают.
- mypy strict без глобальных ослаблений: `ignore_missing_imports` и `# type: ignore` не используются; override допустим только точечно, для модуля без типов.
- Тест на модуль — `tests/test_<модуль>.py`.
- Документы для тестов генерируются в самих тестах через `tests/builders.py`; данные только выдуманные («ООО «Ромашка»», «Арендатор»), без настоящих имён, адресов и реквизитов.
